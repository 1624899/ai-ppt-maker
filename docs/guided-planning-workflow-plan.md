# 分步规划工作流开发任务文档

## 目标

为现有 PPT 生成系统新增两种生成工作流：

- 一键生成：用户配置好主题、页数、风格和素材后，系统直接跑完整生成链路，默认模式。
- 分步规划：用户先得到模型规划草案，再通过规划编辑、自由对话、素材引用和确认动作逐步控制生成过程。

这份文档聚焦“模型规划可展示、可编辑、可确认、可由对话自动沉淀为变更”的产品与工程任务。


## 核心判断

分步规划不是伪需求。它解决的是 PPT 创作中最常见的问题：用户一开始并不总是知道自己要什么，需要边讨论、边看结构、边调整，再生成视觉结果。

但对话不能只停留在聊天层。可用的 Agent 工作流必须把自由讨论沉淀成结构化变更：

```text
自由讨论 -> Agent 归纳意图 -> 生成变更草案 -> 用户确认 -> 修改规划或重跑生成
```

系统需要区分三类内容：

- 对话内容：自由探索、解释、追问、比较方案。
- 规划内容：可编辑的结构化 PPT 蓝图。
- 执行内容：对规划、页面、图片或导出的可执行变更。


## 用户流程

### 一键生成

适合用户已经有明确目标、希望直接得到结果的场景。

```text
配置方案 -> 模型规划 -> 原稿图生成 -> 元素图生成 -> 可编辑 PPT 导出
```

行为要求：

- 默认选中一键生成。
- 创建任务后不中断等待用户确认。
- 中间仍可查看进度、页面结构和预览。
- 用户可主动停止生成，之后基于已有结果继续修改。


### 分步规划

适合用户希望把控内容结构、视觉方向和页面生成质量的场景。

第一阶段推荐只在规划阶段设置确认门槛：

```text
配置方案 -> 生成规划草案 -> 用户编辑或对话讨论 -> 确认规划 -> 继续生成后续产物
```

后续可演进为更细的确认链路：

```text
确认规划 -> 生成原稿图 -> 确认原稿图 -> 生成元素图 -> 确认元素图 -> 导出 PPT
```


## 信息架构

### 顶栏

新增模式切换控件：

```text
一键生成 | 分步规划
```

建议规则：

- 默认选择“一键生成”。
- 模式影响新任务创建时的执行策略。
- 已创建任务展示当前模式，但不建议随意切换任务模式。
- 如需中途干预，应通过“停止生成”“继续生成”“应用变更后重新生成”等动作完成。

建议字段：

```json
{
  "workflow_mode": "auto"
}
```

可选值：

- `auto`：一键生成。
- `guided`：分步规划。


### 中间创作工作区

中间区域承担“可编辑源头”和“Agent 协作入口”。

建议将现有工作模式扩展为：

```text
对话 | 规划 | 编辑
```

职责划分：

- 对话：自由讨论、资源引用、上传图片、生成变更草案。
- 规划：展示和编辑整套 PPT 规划。
- 编辑：对已生成页面做单页文字、排版、风格或图片相关修改。


### 右侧 PPT Studio

右侧继续承担“预览与对照”职责。

适合展示：

- 当前页预览。
- 页面结构列表。
- 模型规划摘要。
- 导出结果。

不建议把完整规划编辑放在右侧。右侧宽度有限，适合快速浏览和选择页面，不适合承载整套规划的深度编辑。


## 规划编辑能力

分步规划模式下，模型规划草案生成后应进入可编辑状态。

第一阶段建议支持：

- 编辑 PPT 标题。
- 编辑整体摘要。
- 编辑目标受众。
- 编辑风格方向。
- 调整页面数量。
- 新增、删除、复制、重排页面。
- 编辑单页标题。
- 编辑单页摘要。
- 编辑单页要点。
- 编辑单页视觉建议。
- 确认规划并继续生成。

规划编辑区应支持“草案态”和“已确认态”：

- 草案态：用户可编辑，后续生成尚未开始或已暂停。
- 已确认态：作为后续生成依据，修改后需要再次确认或触发重新生成。


## 对话协作能力

对话模式应支持用户自由表达，而不是要求用户学习固定指令。

用户可以说：

- “第 2、3、4 页逻辑太散，帮我合成一个更像路演的结构。”
- “参考这张图的风格，把案例页做得更有冲击力。”
- “第 5 页和第 7 页都讲成本，能不能换个角度？”
- “把第 3 页改成对比页，但不要重新生成整套。”

Agent 在讨论完成后应生成一个结构化变更草案，而不是直接无提示执行。


## 资源输入与引用

对话模式需要支持用户上传任意辅助图片，不只限于标注过的原稿图。

建议资源类型：

- `style_reference`：风格参考图。
- `content_asset`：内容素材图。
- `markup_image`：用户标注图。
- `reference_page`：页面原稿图。
- `element_page`：元素图。
- `planning_page`：某页规划。
- `temporary_image`：临时讨论图。

引用方式建议做成可解析资源，而不是纯文本：

```text
@第3页规划
@第5页原稿图
@第2页元素图
@上传图片-竞品截图
```

前端展示为资源 chip，后端接收为结构化引用。

建议数据结构：

```json
{
  "resource_ref": {
    "type": "planning_page",
    "job_id": "job_123",
    "page_no": 3,
    "resource_id": "page_plan_3",
    "label": "第3页规划"
  }
}
```


## Agent 变更草案

Agent 从对话中沉淀出的结果应先成为“变更草案”，由用户确认后执行。

建议字段：

```json
{
  "draft_id": "draft_001",
  "source": "chat",
  "summary": "将第2到第4页合并为一条路演叙事，并重生成第3页原稿图。",
  "affected_scope": {
    "planning": true,
    "pages": [2, 3, 4],
    "images": ["reference"],
    "export": false
  },
  "operations": [
    {
      "type": "update_page_plan",
      "page_no": 3,
      "patch": {
        "title": "市场机会与用户痛点",
        "summary": "用一页建立需求强度、市场规模和当前方案缺口。"
      }
    },
    {
      "type": "regenerate_reference_image",
      "page_no": 3,
      "reason": "页面叙事结构变化，需要重新生成原稿图。"
    }
  ],
  "requires_confirmation": true
}
```

第一阶段建议支持的操作类型：

- `update_deck_plan`：修改整套规划字段。
- `update_page_plan`：修改单页规划。
- `add_page_plan`：新增页面规划。
- `delete_page_plan`：删除页面规划。
- `reorder_pages`：调整页面顺序。
- `regenerate_reference_image`：重生成原稿图。
- `regenerate_element_image`：重生成元素图。
- `rebuild_export`：重新导出 PPT。


## 任务状态建议

分步规划需要比一键生成多一个“等待确认”的状态。

建议新增状态或阶段状态：

- `awaiting_plan_confirmation`：等待用户确认规划。
- `awaiting_reference_confirmation`：后续扩展，等待确认原稿图。
- `awaiting_element_confirmation`：后续扩展，等待确认元素图。

第一阶段可只实现：

```text
planning running -> awaiting_plan_confirmation -> reference_generation running
```

确认动作发生后，再继续后续阶段。


## 数据模型建议

### 任务元信息

建议写入 `job_meta`：

```json
{
  "workflow_mode": "guided",
  "confirmation_policy": {
    "plan": true,
    "reference_pages": false,
    "element_pages": false,
    "export": false
  }
}
```

### 规划版本

规划应支持版本化，避免用户和 Agent 多轮讨论后无法回退。

建议新增：

```json
{
  "plan_versions": [
    {
      "version_id": "plan_v1",
      "source": "model",
      "created_at": "2026-05-30T23:59:00",
      "summary": "模型初始规划",
      "pages": []
    },
    {
      "version_id": "plan_v2",
      "source": "user_confirmed",
      "created_at": "2026-05-31T00:08:00",
      "summary": "用户调整后的确认规划",
      "pages": []
    }
  ],
  "active_plan_version_id": "plan_v2"
}
```


## 前端改造建议

### 新增组件

建议优先新增文件，保持模块解耦。

- `web_ui/src/components/Workspace/WorkflowModeSwitch.jsx`
  - 顶栏或任务配置区的模式切换。
- `web_ui/src/components/Workspace/PlanningEditor.jsx`
  - 中间区域的整套规划编辑器。
- `web_ui/src/components/Workspace/PagePlanEditor.jsx`
  - 单页规划编辑。
- `web_ui/src/components/Workspace/AgentChangeDraft.jsx`
  - 展示 Agent 从对话中生成的变更草案。
- `web_ui/src/components/Workspace/ResourceReferencePicker.jsx`
  - 对话输入中的资源引用选择器。
- `web_ui/src/components/Workspace/ChatAttachmentInput.jsx`
  - 对话图片上传入口。

### 工具函数

- `web_ui/src/utils/workflowMode.js`
  - 模式默认值、标签、按钮文案、是否需要确认。
- `web_ui/src/utils/planningDraft.js`
  - 规划草案归一化、前端展示模型转换。
- `web_ui/src/utils/resourceReferences.js`
  - 资源引用归一化和展示标签生成。

### 交互文案

模式切换：

- 一键生成：按钮文案为“开始生成”。
- 分步规划：按钮文案为“生成规划”。

规划确认：

- “确认规划并继续生成”
- “保存为草案”
- “让 Agent 重新规划”
- “应用变更草案”


## 后端改造建议

### 新增模块

- `ppt_system/web/services/workflow_policy.py`
  - 根据 `workflow_mode` 决定阶段是否自动继续。
- `ppt_system/web/services/plan_version_store.py`
  - 管理规划版本、当前激活版本和回退。
- `ppt_system/web/services/agent_change_draft.py`
  - 将对话结果归一化为结构化变更草案。
- `ppt_system/web/services/resource_reference_resolver.py`
  - 根据前端资源引用解析真实规划、图片和上下文。

### 新增接口

- `POST /api/jobs`
  - 接收 `workflow_mode`。
- `GET /api/jobs/<job_id>/plan`
  - 获取当前规划、版本和确认状态。
- `PUT /api/jobs/<job_id>/plan`
  - 保存用户编辑后的规划草案。
- `POST /api/jobs/<job_id>/plan/confirm`
  - 确认规划并继续生成。
- `POST /api/jobs/<job_id>/agent/change-drafts`
  - 根据对话上下文生成变更草案。
- `POST /api/jobs/<job_id>/agent/change-drafts/<draft_id>/apply`
  - 应用变更草案。
- `POST /api/jobs/<job_id>/attachments`
  - 上传对话图片或素材图片。
- `GET /api/jobs/<job_id>/resources`
  - 返回可引用资源列表。


## MVP 范围

第一阶段建议控制范围，避免一次性做成复杂创作平台。

必须实现：

- 顶栏或任务配置区支持“一键生成 / 分步规划”切换。
- 新任务创建时写入 `workflow_mode`。
- 一键生成保持当前自动完整链路。
- 分步规划只跑到模型规划阶段并暂停。
- 中间区域新增“规划”模式。
- 用户可编辑整套规划和单页规划。
- 用户可确认规划并继续生成。
- 对话区可生成结构化变更草案。
- 用户可确认应用变更草案到规划。

暂缓实现：

- 每个阶段都强制确认。
- 图片上传后的复杂素材管理。
- 多人协作。
- 完整撤销重做。
- 自动随时无确认地修改规划和图片。
- 对所有历史对话做长期记忆。


## 开发阶段拆分

### 阶段 1：模式切换与任务策略

目标：

- 用户创建任务时可以选择一键生成或分步规划。
- 后端能按模式决定是否暂停在规划阶段。

任务：

- 新增工作流模式常量与默认值。
- 创建任务接口接收 `workflow_mode`。
- 任务详情返回 `workflow_mode`。
- 后端阶段编排支持 `awaiting_plan_confirmation`。
- 前端创建表单和顶栏展示当前模式。

验收：

- 一键生成任务能继续跑完整链路。
- 分步规划任务在模型规划完成后暂停，页面显示等待确认。


### 阶段 2：规划编辑器

目标：

- 用户能在中间区域查看和编辑模型规划。

任务：

- 新增 `PlanningEditor`。
- 新增 `PagePlanEditor`。
- 支持编辑整体规划字段和页面字段。
- 支持新增、删除、复制、重排页面。
- 保存规划草案。
- 确认规划并继续生成。

验收：

- 修改规划后刷新页面仍能看到最新草案。
- 点击确认后，后端使用最新规划继续生成。


### 阶段 3：对话沉淀为变更草案

目标：

- 用户在对话中讨论后，Agent 能生成可确认的变更草案。

任务：

- 扩展对话接口，返回 `change_draft`。
- 新增 `AgentChangeDraft` 展示影响范围和操作列表。
- 支持用户应用或放弃草案。
- 应用草案后更新规划草案。

验收：

- 用户输入“把第 2、3 页合并成一页”后，界面出现变更草案。
- 用户确认后，规划页数和相关页面内容发生变化。


### 阶段 4：资源引用与图片输入

目标：

- 用户可在对话中引用规划、原稿图、元素图和上传图片。

任务：

- 新增资源列表接口。
- 新增图片上传接口。
- 对话输入支持资源 chip。
- 后端根据资源引用装配 Agent 上下文。

验收：

- 用户可 `@第3页规划` 或 `@第5页原稿图` 发起讨论。
- Agent 生成的草案能正确声明影响范围。


## 测试建议

### 单元测试

建议新增：

- `tests/test_workflow_policy.py`
  - 验证一键生成和分步规划的阶段推进策略。
- `tests/test_plan_version_store.py`
  - 验证规划版本保存、激活和回退。
- `tests/test_agent_change_draft.py`
  - 验证变更草案归一化和操作校验。
- `tests/test_resource_reference_resolver.py`
  - 验证资源引用解析。

### 集成测试

覆盖以下流程：

1. 创建一键生成任务，确认不会停在规划阶段。
2. 创建分步规划任务，确认规划完成后进入等待确认状态。
3. 修改规划并确认，确认后续阶段继续执行。
4. 从对话生成变更草案，应用后规划内容变化。
5. 引用多页规划或页面图片，确认后端能解析资源上下文。

### 泛化测试

避免只针对单个输入写死逻辑，至少覆盖：

- 3 页、8 页、15 页规划。
- 删除第一页、中间页、最后一页。
- 多页合并。
- 新增页面后重排。
- 同时影响规划和图片重生成的草案。
- 引用单个资源和多个资源。


## 风险与处理

### 风险 1：分步规划过于繁琐

处理：

- 默认仍是一键生成。
- 第一阶段只在规划阶段暂停。
- 后续阶段确认做成可选高级设置。


### 风险 2：对话变成黑盒执行

处理：

- 对话只生成变更草案。
- 草案明确展示影响范围、操作列表和是否重生成。
- 用户确认后才落地。


### 风险 3：规划编辑和页面编辑边界混乱

处理：

- 规划编辑只改结构化蓝图。
- 页面编辑改已生成页面内容、排版和视觉。
- 涉及重生成时必须写明影响范围。


### 风险 4：资源引用不可解析

处理：

- 前端使用资源 chip。
- 后端接收结构化 `resource_ref`。
- 不依赖纯文本 `@` 名称猜测。


### 风险 5：规划版本不可回溯

处理：

- 每次模型规划、用户保存、草案应用、用户确认都产生版本。
- 后续可在 UI 中暴露版本历史。


## MVP 验收标准

满足以下条件即可认为第一阶段完成：

- 顶栏或创建区有“一键生成 / 分步规划”模式切换，默认一键生成。
- 一键生成行为与现有完整生成链路一致。
- 分步规划任务会在模型规划完成后暂停。
- 中间区域可以查看、编辑并保存模型规划。
- 用户确认规划后，任务继续生成原稿图、元素图和 PPT。
- 对话区可以根据用户讨论生成结构化变更草案。
- 用户确认变更草案后，规划会被自动修改。
- 右侧 PPT Studio 能继续展示页面结构、当前预览和导出结果。


## 后续演进

建议按价值逐步扩展：

1. 增加原稿图确认节点。
2. 增加元素图确认节点。
3. 支持更多资源类型和素材库管理。
4. 支持对话中直接选择应用到规划、应用到当前页、应用到整套风格。
5. 支持规划版本对比和回退。
6. 支持从用户上传图片中提取风格、结构或内容素材。
7. 支持自动生成多个规划方案供用户选择。
