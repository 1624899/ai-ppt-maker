# 规划审校与生图 Prompt 传递改造任务

## 背景

分步规划模式下，用户会先看到 AI 生成的页面规划，再对标题、摘要、要点、视觉建议和提示词进行人工删改。当前体验存在两个核心问题：

- 用户修改后如果没有保存，点击顶部或右侧的确认生成入口，可能仍按服务端旧规划继续生成。
- 前端展示的“原稿图提示词”容易让用户误以为它就是唯一会传给生图模型的内容，但实际还存在第一阶段原稿图最终提示词和第二阶段元素图提示词。

本次改造不做复杂版本管理，只保证用户当前看到和确认的规划能稳定成为生成使用的规划。

## 产品原则

- 用户当前屏幕上的规划草稿，就是用户期望生成使用的内容。
- 不引入版本列表、版本命名、回滚入口等复杂管理能力。
- 只区分“已保存规划”“当前草稿”“是否有未保存修改”。
- 所有确认生成入口必须表现一致。
- 哪些 Prompt 最终会传给生图模型，需要在界面上清楚展示。

## 本次实现范围

1. 建立共享规划草稿状态
   - 将规划草稿从 `PlanningEditor` 内部提升到工作台层。
   - 维护当前任务的 `planDraft`、`savedPlan`、`dirty`、加载状态和错误状态。
   - 让 `PlanningEditor`、顶部 Header、右侧 PPT Studio 共享同一份规划草稿。

2. 统一确认规划入口
   - 顶部“确认规划”按钮、右侧“确认规划并继续”按钮、规划编辑器内部按钮都走同一个确认方法。
   - 确认时如果存在当前草稿，调用确认接口并传入 `planDraft`。
   - 避免任何入口绕过当前编辑器草稿直接使用服务端旧规划。

3. 增加未保存修改拦截
   - 如果用户有未保存修改并点击确认生成，弹出确认框。
   - 弹窗提供三个选择：
     - 保存修改并开始生成
     - 放弃修改，按已保存规划生成
     - 继续编辑
   - 不让系统静默使用旧规划。

4. 简化版本管理露出
   - 移除规划编辑器中的“规划版本”展示。
   - 后端内部如仍需要计划快照用于运行态一致性，暂不强拆，避免影响流水线。

5. Prompt 可见性优化
   - 将“原稿图提示词”改名为“原稿图最终提示词”。
   - 展示并允许编辑“元素图提示词”。
   - 增加简短提示，说明这些字段是实际生成阶段会使用的 Prompt。

## 后续扩展点

- 内容字段变更后自动重建最终提示词。
- 区分“系统自动生成 Prompt”和“用户手动覆盖 Prompt”。
- 增加“根据当前页面内容重新生成提示词”入口。
- 在任务日志或调试面板中展示最终传给生图模型的请求摘要。

## 验收标准

- 修改规划后不保存，点击任意确认生成入口，都会弹出未保存修改确认框。
- 选择“保存修改并开始生成”后，后端收到当前草稿并继续生成。
- 选择“放弃修改，按已保存规划生成”后，丢弃当前草稿并按已保存规划继续生成。
- 选择“继续编辑”后，弹窗关闭，不触发生成。
- 顶部、右侧、规划编辑器内三个入口行为一致。
- 规划编辑器不再展示版本列表。
- 页面编辑器能看到原稿图最终提示词和元素图提示词。

## 详细规划
一、核心原则

这套流程不做复杂版本管理。

用户心智应该是：

我看到并修改的当前规划，就是我希望最终生成 PPT 和图片时使用的规划。

所以系统只需要区分：

已保存规划
当前编辑草稿
是否有未保存修改
不需要历史版本、版本列表、回滚、命名版本这些东西。

二、未保存修改的生成拦截

这是最高优先级。

现在的问题是：用户改了规划但没保存，如果习惯性点“开始生成”，可能会按旧规划生成。

需要修改为：

规划编辑后标记为 dirty
用户点击任何“开始生成 / 确认规划 / 继续生成”入口时，先检查是否有未保存修改
如果没有未保存修改，直接生成
如果有未保存修改，弹窗确认
弹窗建议：

标题：

检测到未保存修改

说明：

你刚才修改了规划内容。开始生成前，可以先保存这些修改，或放弃修改并使用上一次保存的规划。

按钮：

保存修改并开始生成
放弃修改，按已保存规划生成
继续编辑
这里不要做“版本管理”，只是避免用户误用旧内容。

三、统一所有生成入口

目前规划编辑器内部的确认按钮会带当前 plan，但顶部 Header 和右侧 PPTStudio 的按钮可能直接走后端 action，导致没有带上编辑器里未保存的草稿。

要改成：

顶部按钮
右侧按钮
规划编辑器里的确认按钮
全部走同一个方法，例如：

confirmCurrentPlan()
这个方法统一负责：

检查是否有未保存修改
弹窗
保存当前草稿
确认规划
开始生成
这样不会出现“从不同按钮进入，结果行为不一致”的问题。

四、前端状态提升

现在 PlanningEditor 内部自己维护本地 plan，但 Header / PPTStudio 拿不到这个草稿。

建议把规划草稿状态提升到 WorkspaceShell：

planDraft
setPlanDraft
planDraftDirty
savedPlan
confirmCurrentPlan
然后传给：

PlanningEditor
Header
PPTStudio
这样整个工作台看到的是同一份当前草稿。

五、保存与生成的关系

建议保留“保存修改”按钮，但它只表示：

把当前规划保存到后端。

不需要叫“保存版本”。

当用户点击“保存修改并开始生成”时，系统应该自动完成：

保存当前草稿
后端重新规范化规划
重新得到最终图片 prompt
开始生成
也就是说，用户不需要先点保存再点生成。

六、需要明确展示：哪些 prompt 最终传给生图模型

目前容易误导用户，因为界面展示的是“原稿图提示词”，但实际流程里规划模型返回的 image_prompt 不一定就是最终传给生图模型的 prompt。

需要在界面上明确区分：

页面内容规划：标题、摘要、要点、视觉建议
原稿图最终提示词：最终传给第一阶段生图模型
元素图提示词：最终传给第二阶段元素图模型
建议把“原稿图提示词”改名为：

原稿图最终提示词

并增加说明或状态提示：

这是生成页面原稿图时实际使用的提示词。

elements_prompt 可以先放到高级区域，不一定默认展开。

七、prompt 同步规则

这个是第二优先级，但很重要。

用户修改页面标题、摘要、要点、视觉建议后，不能继续沿用旧的 image_prompt，否则会出现：

文案改了，但图片还是按旧意图生成。

建议规则：

用户只改页面内容字段
保存或生成时，自动根据最新内容重建最终 prompt。

用户直接改“原稿图最终提示词”
视为手动覆盖，后端不要再自动覆盖它。

用户直接改“元素图提示词”
同样视为手动覆盖。

如果 prompt 已经过期，界面可以显示：

页面内容已修改，提示词将在保存/生成时同步更新。

也可以提供一个按钮：

根据当前页面内容重新生成提示词

八、后端需要配合的点

后端确认规划时不能只拿旧服务端 plan。

需要支持：

confirmJobPlan(jobId, {
  plan: planDraft,
  summary: '用户确认规划并继续生成'
})
后端收到最新 plan 后要做：

normalize plan
保存 plan
根据最新 plan 重建最终 page.image_prompt
必要时重建 elements_prompt
再进入图片生成任务
重点是：生成任务最终拿到的一定是刚保存后的规划，而不是旧规划。

九、图片 prompt 流程需要在界面和日志里讲清楚

现有流程可以概括为：

AI 规划阶段生成初始页面规划
planner_image_prompt 保存原始规划 prompt
后端根据参考模式重建 page.image_prompt
第一阶段原稿图使用 page.image_prompt
第二阶段元素图使用 elements_prompt
图片标注编辑走另一条 image_edit_prompt，不属于规划 prompt
建议前端至少展示第 4 和第 5 项，也就是最终真实传给生图模型的 prompt。

十、最终推荐实施顺序

第一阶段，先修体验闭环：

规划草稿状态提升到 WorkspaceShell
增加 dirty 判断
所有生成入口统一走 confirmCurrentPlan
有未保存修改时弹窗
“保存修改并开始生成”传当前草稿给后端
第二阶段，修 prompt 可见性：

改名“原稿图最终提示词”
增加 elements_prompt 展示
标明哪些 prompt 会实际传给模型
第三阶段，修 prompt 同步：

内容字段修改后标记 prompt 过期
保存/生成时自动重建 prompt
手动改过 prompt 时保留用户覆盖
增加“根据当前页面内容重新生成提示词”按钮
