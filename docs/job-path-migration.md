# 任务路径迁移说明

## 背景

旧版本会把任务目录的 Windows 绝对路径写入 `jobs.sqlite3`，例如：

```text
C:\Users\旧用户名\AppData\Roaming\AI PPT Maker\output\job-123
```

数据库和任务目录复制到其他电脑或其他 Windows 用户后，该绝对路径会失效。

## 正式方案

新任务不再持久化机器相关的绝对路径。位于 `jobs.sqlite3` 同目录下的任务目录保存为相对引用，例如：

```text
job-123
```

读取任务时，以当前机器上的 `jobs.sqlite3` 所在目录为基准解析：

```text
<当前 output 目录>\job-123
```

位于数据库目录之外的用户自定义任务目录仍保存为绝对路径，保持其外部目录语义。

正式实现位于 `ppt_system/jobs/job_store.py`：

- `_serialize_job_directory()`：写入数据库前生成可迁移引用；
- `resolve_job_directory()`：读取数据库后解析当前机器上的实际路径；
- `create_job()`、`update_job()`、`get_job()` 和 `list_jobs()`：统一经过上述边界。

## 临时历史数据迁移

`_normalize_job_directory_references()` 是临时保留的旧数据迁移逻辑，由 `init_db()` 在数据库初始化时执行。

处理规则：

1. 已是相对路径的记录不处理；
2. 旧绝对路径仍然存在时，仅在该目录位于当前数据库目录下时转换成相对路径；
3. 旧绝对路径已失效，但当前数据库目录下存在 `<job_id>` 目录时，转换成该相对路径；
4. 无法确认对应目录时保持原值，不根据其他目录或同名文件进行猜测；
5. 该过程只修改数据库中的路径引用，不复制、移动或删除任务文件。

## 删除条件

不要自行删除 `_normalize_job_directory_references()`。

只有满足以下条件，并收到项目负责人明确通知后，才能删除：

1. 所有需要保留历史任务的电脑均已至少启动一次包含该迁移逻辑的版本；
2. 每台电脑的旧任务均已确认可以打开；
3. 数据库中的内部任务路径已确认转换为相对引用；
4. 项目负责人明确通知删除临时迁移逻辑。

删除时应同时删除：

- `_normalize_job_directory_references()`；
- `init_db()` 中对该函数的调用；
- 仅覆盖旧绝对路径转换的测试；
- 本文档中的临时迁移章节或将本文档标记为已完成。

正式的相对路径存储与解析逻辑不得删除。
